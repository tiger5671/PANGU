# PANGU 优化阶段记录（2026-10-15）

本文记录本次提交前已完成的实现、验证结果和未完成事项，供后续继续开发和对比评估使用。论文及回复信保留在本地 `doc/`，固件保留在本地 `firmware/`；二者及分析产物均不纳入本次提交。

**当前结论：基础分析、证据约束、审核状态和离线运行能力已得到改进，自动化测试通过；尚未证明整体检出率、误报率或分析效率优于原项目，也尚未完成真实固件上的完整双角色语义审核。**

## 1. 已完成的研究与设计梳理

- 阅读了 `doc/Main_Manuscript.pdf` 和 `doc/PANGU_Response_Letter.pdf`，梳理了文件系统预分析、路由恢复、上下文回溯、逻辑解耦、ACDG、Detective 与 Reviewer 的主流程。
- 对照主入口、分析模块、IDA 桥接和模型封装检查了实现，修复了会阻断导入或运行的语法及接口问题。
- 参考了 [IDA-Skill](https://github.com/miunasu/IDA-Skill) 的按需查询、函数上下文收集和命令行分析思路。本次新增能力由本项目实现，未直接复制或集成该仓库代码；其全部工具能力尚未移植。

后续优化采用以下语义约束：

1. `Auth-Required` 表示观察到检查，不表示检查有效；该类路由仍须接受审核。
2. `Auth-Free` 只描述当前分析范围内未观察到相应检查，不能直接推导公网可达或存在漏洞。
3. 初始化/注册时的调用关系不能替代请求处理时的支配关系。
4. TIS 是候选筛选指标，函数名、路径名和高 TIS 都不能单独证明认证或授权语义。
5. CFG 路径是结构证据，尚不能证明某个请求能实际走通该路径。
6. 缺失证据、解析失败和工具错误必须保留为未解决状态。

## 2. 已实现的更改

### 2.1 运行基础与模型接口

- 修复模型类方法缩进、路由提取表达式和 IDA visitor 构造等语法问题，使核心模块可以编译和导入。
- 将可选模型 SDK 和精确 tokenizer 改为按需加载，避免仅导入分析模块就下载 tokenizer 或强制依赖未使用的模型 SDK。
- 模型配置在创建 provider 时读取；增加配置检查、请求超时和总尝试次数上限，移除无法反映实际调用的固定成本估算。
- 优先记录服务返回的 token 用量；未启用精确 tokenizer 时使用明确标注的估计值。
- 主流程在模型配置或结构化响应预检失败时停止；有效的无发现分析不再因发现数为零而被视为失败。

主要文件：`core/llm.py`、`PANGU.py`。

### 2.2 IDA 通信与证据采集

- 新增公共帧协议处理，支持分片接收、EOF 检测、帧大小上限和接收期限，修复部分读导致解析错误或连接长期等待的问题。
- 客户端串行处理同一连接的请求/响应，丢弃失败连接，避免重复连接泄漏；服务端支持多个客户端，IDA 操作仍交给主线程执行。
- 增加受限批量只读查询、反编译分页、分支覆盖分析、二进制身份和能力信息；未增加任意代码执行接口。
- 新增 `EvidenceCollector`：记录工具参数、结果及 SHA-256，生成可引用的证据编号；为查询提供缓存、预算和失败记录。
- 候选结论需要引用实际存在且成功的证据，代码引文必须是相应反编译结果中的连续片段。
- 函数上下文支持有界的多层调用收集，共享函数结果复用；分流、调查和复核分别有查询预算。

主要文件：`core/bridge/protocol.py`、`ida_client.py`、`ida_server.py`、`analysis/evidence.py`。

### 2.3 支配关系、TIS 和安全语义

- 新增不依赖 IDA 的图算法模块，修复循环及不可达前驱下的支配关系和直接支配者计算。
- 增加目标相关的分支覆盖结构证据及绕行路径，避免只关注高 TIS 分支。
- 改进 TIS 对隐式后继、循环初始化/更新和终止行为的处理；使用 `exit`、`fallthrough`、`unknown` 区分已知和未知结果。
- 未解析的 `goto`、复杂循环、间接控制转移等不再直接当作确定终止；结合已知 `noreturn` 信息，并修复真实 IDA ctree 对象访问差异。
- `get_callees` 仅收集实际调用指令，避免把函数内跳转当作函数调用。
- 认证/授权分类需要代码引文与理由，不能仅依靠名称或 TIS；全局 gatekeeper 的覆盖还需要请求上下文和支配关系证据。

**实现边界：**当前 TIS/终止分析仍主要基于 ctree 结构，不是完整的 CFG 区域及共享后继建模，也不是请求级路径可行性证明。

主要文件：`core/graph_analysis.py`、`core/bridge/cfg_analysis.py`、`ida_server.py`、`analysis/security_semantics.py`、`logic_decoupler.py`。

### 2.4 路由恢复与认证状态

- 修复只处理前 30 个注册表的问题，改为遍历全部批次；增加返回表编号与分类结果校验。
- 去重时保留大小写、HTTP 方法、二进制、逻辑 selector 和挂载上下文差异。
- 新增多层、多父挂载关系回溯；在循环、缺失引用或预算耗尽时保留有证据支持的部分路径及分析缺口。
- 挂载前缀要求真实调用引用和代码片段，不再接受模型凭空补全父路径或通用前缀。
- 区分逻辑 action/JSON-RPC 方法与实际 URL，未解析的映射明确标记。
- 保守处理未知认证状态：文件名和方法名不能直接证明受保护；上游白名单提示不能抹除 handler/CGI 中观察到的本地检查。
- 修复大端 ELF 架构读取、64 位指针表以及将所有架构地址都按 ARM Thumb 方式处理的问题。

主要文件：`analysis/route_hierarchy.py`、`route_extractor.py`、`logic_decoupler.py`、`jsonrpc_extractor.py`、`distributed_cgi_extractor.py`、`fastcgi_extractor.py`、`firmware_analyzer.py`、`scripts/ida/scan_function_pointer_tables.py`。

### 2.5 双角色检测与报告

- 主入口复用统一的 `DualAgentDetector`，注入实际 IDA 客户端和模型 provider，避免连接配置不一致。
- 调查范围包含 `Auth-Free`、`Auth-Required` 和 `Unknown`，不再仅取前 5 个免认证路由或前 3 个 gatekeeper。
- 默认路由预算为 50，`--max-routes 0` 表示全部；超预算及其他二进制的路由列入延期分析清单。
- Detective 在模型判断前先收集实际代码，区分候选、无发现和证据不足。
- Reviewer 独立收集复核证据，使用 `SUPPORTED`、`REJECTED`、`UNRESOLVED`；只有严格结构化检查通过且证据有效的候选才进入支持结果。
- 空响应、错误 JSON、工具失败或证据不足不再默认保留为已验证漏洞。RAG 信息只作为线索。
- 报告记录二进制身份、覆盖范围、各认证状态调查数、延期原因、工具预算、缓存命中和未解决审核。
- ACDG/路由增加认证引用、挂载链、selector、解析状态、分析缺口及二进制身份；保留旧数据加载的默认值，并修复序列化/加载时的字段丢失。

**结果含义：**`SUPPORTED` 是当前静态证据和审核规则支持的结论，不等同于已经动态复现。两个角色使用同一个 provider 时，也不意味着两个独立模型。

主要文件：`analysis/models.py`、`detective_agent.py`、`reviewer_agent.py`、`dual_agent_detector.py`、`pangu_pipeline.py`、`PANGU.py`。

### 2.6 无头 IDA、快照与无 API 审核

- 新增 `scripts/ida_snapshot.py`，将输入二进制或 IDA 数据库复制到临时目录，在副本上运行 IDA，保留日志并原子发布快照。
- 子进程使用参数列表、关闭 shell、设置超时；查询限制为已支持的只读命令。
- 新增严格快照客户端和 `--ida-snapshot`。没有录入的查询返回错误，不能据此假装分析完整。
- 新增文件审核模式 `--review-mailbox`，无需模型 API：缺少响应时持久化请求并以退出码 2 暂停；人工或当前助手阅读证据并提供响应后，重跑同一命令继续。
- 审核响应绑定完整提示、调用角色和模式的哈希；提示或证据改变后不复用旧响应，错误的请求编号会被拒绝。

**完成状态：**文件交换、暂停和重放已经通过测试；尚未由当前助手完成真实固件样本的完整 Detective → Reviewer 审核。该模式需要实际审核者填写响应，不会自动调用当前对话模型。

主要文件：`scripts/ida_snapshot.py`、`core/bridge/snapshot_client.py`、`core/review_mailbox.py`、`PANGU.py`。

### 2.7 跨二进制存储通道候选

- IDA 可提取 NVRAM 类 API 的常量键读写点，保留调用者、地址、二进制身份和未解析项。
- 新增 `StorageGraph` 和 `scripts/link_storage_snapshots.py`，在明确指定的同一固件范围内连接不同二进制的同名键写入/读取证据。
- 主入口通过 `--storage-graph` 加载，要求固件编号匹配，并向调查/审核工具提供相关候选链接。

**实现边界：**这些链接明确标记为 `CANDIDATE_CHANNEL`、`taint_verified=False`。尚未证明攻击者可控、数据实际传播、执行时序或完整的跨进程访问控制绕过；它们不是已确认的数据流。

主要文件：`analysis/storage_graph.py`、`scripts/link_storage_snapshots.py`、`core/bridge/ida_server.py`、`analysis/evidence.py`。

## 3. 已完成的验证

### 3.1 自动化测试

本机环境为 Windows、Python 3.12.7、IDA Pro 9.0。依赖安装在被忽略的 `.runtime/` 中。

```powershell
$env:PYTHONPATH = "$PWD\.runtime"
python -m pytest -q
python -m compileall -q PANGU.py analysis core scripts tests/unit
git diff --check
```

- 测试结果：**59 passed，2 warnings**。
- 两个警告来自原有 `tests/test_integration.py` 的测试函数返回非 `None` 值，尚未整理，不是本轮测试失败。
- `pytest.ini` 默认运行 `tests/unit` 和上述 mock 集成测试，不包含全部需要现场 IDA/API 的手工测试脚本。
- 覆盖分片通信、EOF、帧大小、支配关系、证据校验、模型失败、审核状态、路由上下文、数据兼容、快照发布、存储候选及审核邮箱。
- 支配关系测试包括 80 个固定随机种子小图，与穷举简单路径得到的结果对比。
- 文件审核 CLI 测试验证“缺响应退出 2 → 填写匹配响应 → 重跑退出 0”；使用合成数据和显式证据不足结论，不是实际漏洞评估。

## 5. 下一阶段优先顺序

1. **完成一个真实样本的可重放审核闭环。** 使用已采集的 IDA 证据和文件审核模式，由当前助手执行实际阅读与反证检查，先验证证据不足也能正确收敛；缺失查询再定向补采。
2. **建立小型人工标注基准。** 同时包含有检查、无检查、检查无效和信息不足的场景，比较路由完整性、认证分类和最终审核结果，避免只用发现数量评价效果。
3. **加强请求上下文。** 优先补齐入口 → dispatcher → handler → 敏感操作的证据链及检查覆盖，再扩展复杂控制流和间接调用。
4. **将存储候选推进为可验证数据流。** 从有限的同固件常量键开始，逐步加入来源、值传播和时序约束；IPC 和脚本协作在此基础上扩展。
5. **根据基准决定新方法。** 评估上下文图、需求驱动分析、摘要缓存和反例导向复核的收益，再增加模型规模或查询预算。
